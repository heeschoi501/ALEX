# practice_v013.py — 힌트만

정답 코드는 적지 않는다. 막혔을 때 한 단계씩만 본다.

## 문제 1 — Profile
1. 입력 문자열의 앞뒤 공백을 제거한다.
2. 대문자로 통일한다.
3. `DESKTOP`인지 한 번만 비교하면 된다.

## 문제 2 — Root boundary
1. 두 Path 모두 `resolve()`한다.
2. candidate == root인 경우도 허용해야 한다.
3. 그 외에는 `root in candidate.parents`를 생각해 본다.

## 문제 3 — Secret redaction
1. `re.sub()`을 찾아본다.
2. key 이름과 `=`까지는 유지하고 값만 바꾼다.
3. 대소문자 무시 옵션을 생각한다.

## 문제 4 — 빈도
1. `collections.Counter`를 써도 된다.
2. `sorted(..., key=...)`에서 count에는 minus를, name에는 원래 값을 사용하면 두 조건을 동시에 표현할 수 있다.

## 문제 5 — Context budget
1. 최신 항목부터 거꾸로 확인한다.
2. 항목 수와 문자 수를 **둘 다** 검사한다.
3. 마지막에 다시 원래 시간 순서로 뒤집는다.
4. 최신 항목 하나가 너무 길면 예외 처리한다.

## 문제 6 — Cache
조건은 두 개뿐이다. `and`를 사용한다.

## 문제 7 — Byte formatter
1. 단위를 `['B', 'KiB', 'MiB', 'GiB']`로 둔다.
2. 값이 1024 이상일 때 1024로 나눈다.
3. 음수 검사는 맨 먼저 한다.

## 문제 8 — 순서 보존 중복 제거
1. 결과 list와 `seen` set을 따로 둔다.
2. set은 “이미 봤는지”만 빠르게 확인한다.
3. 결과 순서는 list가 책임진다.

## 확인 방식

완성한 뒤 본체 구현을 바로 복사하지 말고 먼저 직접 입력 예시를 만들어 확인한다. 그 다음 비슷한 패턴이 실제 JARVIS 어디에 있는지 검색한다.
