# 2026년 10월 23일 ALEX 개선 기록

정오 공개본 `e2157ca`와 최신 인수인계를 기준으로 검토한 문제를 수정했다. 코딩 모델을 바꾸거나 새 성능 벤치마크를 시작하지 않고, 검증 판정의 정확성·긴 요청 전달·Office 편집 연결과 조사 문맥을 보강했다. 이 기록은 범용 코딩 성공률이 높아졌다는 측정 결과가 아니다.

## 코딩 검사 결과를 재사용하는 조건

- 이전에는 `unittest discover`의 폴더·패턴으로 통과 파일을 추정했다. 이제 별도의 표준 unittest 어댑터가 **실제 실행된 test ID, 정의 파일, 실행·성공·skip 수**를 기록한다. 실행되지 않았거나 전부 skip된 파일, 일부 메서드만 선택한 실행은 파일 전체 통과로 재사용하지 않는다. 독립 검사도 대상 파일의 실제 성공 기록을 요구한다.
- 부모·하위 Workspace가 수정 revision과 실행 기록을 공유한다. 쓰기·편집·패치·되돌리기는 같은 상태를 갱신한다.
- 검사 전후 및 재사용 시 프로젝트 입력의 SHA-256이 일치해야 한다. 같은 크기·같은 시각의 외부 수정도 무효화한다. 기존 합격 검사 원본도 대조한다. 이전 stdout만 있는 기록은 증거로 인정하지 않는다.
- 코드는 물론 일반 프로젝트 fixture·설정 파일도 해시하지만 비공개 데이터·로그·모델·런타임 저장소는 제외한다. 64MiB/16,000파일 한도, 읽기 실패, 연결된 입력 등으로 해시가 불가능하면 캐시를 사용하지 않는다. 외부 서비스·환경 상태까지 고정하는 재현 보장은 아니며 바깥 전체 회귀 검사를 유지한다.
- 별도 임시 bytecode 경로를 사용해 오래된 pyc가 같은 크기·시각의 코드를 대신 검사하지 않게 했다. 어댑터는 설치된 ALEX 안의 경로로 실행하므로 대상 프로젝트에 ALEX 설치가 필요 없다.
- 일꾼 결과에 모델 호출, 도구별 누적 시간, 독립 검사 벽시계 시간을 남긴다. `model`은 주 에이전트 trace에 기록된 호출의 합으로, 압축·하위 모델까지 포함하는 전체 추론 시간이 아니다. 병렬 도구 누적 시간과 벽시계 시간은 더해서 전체 시간으로 해석하지 않는다. 바깥 전체 회귀는 기존 별도 기록을 사용한다.

## 긴 OpenCode 요청

Windows argv에 긴 프롬프트를 넣지 않는다. 짧은 요청은 기존 동작을 유지하고, 긴 요청은 UTF-8 임시 파일 핸들을 **표준입력**으로 전달한다. 성공·시작 실패·취소 때 닫히며 원문을 자르거나 프로젝트 안에 요청 파일을 남기지 않는다. 기본 일꾼을 OpenCode로 바꾸지는 않는다.

설치된 OpenCode `run --help`의 `--file`도 먼저 검토했지만 실제 로컬 가짜 모델로 확인하니 첨부의 뒤쪽 내용이 잘렸다. 이 방식을 채택하지 않고 표준입력을 실제로 검증했다. 한글·따옴표·역슬래시·줄바꿈을 포함한 **105,627자** 요청이 마지막 표식까지 모델 요청에 온전히 도착했고 프로세스가 정상 종료했다. 클라우드·실제 모델·GPU는 사용하지 않았다. 전체 문맥이 모델의 한도를 넘는 문제까지 해결하는 것은 아니다.

프로세스 시작 실패는 `infrastructure_error`로 남기고 자동 수정 기록에서 모델의 수정 실패와 구분한다. 무료 모델 코딩 세션의 출력 스트림도 정상·취소·예외에 닫는다.

## Office 문서 편집

### 대화에 첨부한 문서

워드·엑셀·PPT를 첨부하고 “보고서.docx 고쳐줘”처럼 요청하면 원본을 유지한 편집 사본을 내려받는다. 일반 사용자도 자기 대화의 첨부만 사용할 수 있다. 이어지는 “2장도 다듬어줘”는 마지막 편집 사본을 기준으로 처리한다. 다른 대화의 첨부 ID·내려받기 파일을 이름만으로 선택하지 않는다.

### PC의 프로젝트 문서

관리자만 승인된 프로젝트 안의 `.docx`, `.xlsx`, `.pptx`를 편집할 수 있다. 읽기 전용은 편집하지 않고, 확인 후 실행은 수정안을 보여 준 뒤 채팅 “응”으로 적용한다. 자동 실행 권한이면 바로 적용한다. 적용 전 원본을 데이터 폴더 `backups/office`에 남기고 “되돌려줘”로 복원한다. 승인 전 원본 변경, 프로젝트 변경, 외부 경로·연결 경로, 이후 다른 편집이 있으면 덮어쓰기·되돌리기를 거절한다. 이 작업의 “항상” 답변이 전체 권한을 바꾸지는 않는다.

Office 작업이 더 최근이면 예전 코딩 세션이 “응/되돌려줘”를 가져가지 않는다. 다른 이야기로 넘어간 뒤의 짧은 긍정 답을 오래된 문서 수정 승인으로 사용하지 않는다. 첨부·문서 내용을 자동 교훈으로 승격하지 않는다.

같은 이름의 첨부가 있어도 프로젝트 경로를 명시하면 PC 문서를 선택한다. 문서 적용 후 “응”을 한 번 더 보내도 이전 코딩 세션의 대기 중인 허락으로 전달하지 않는다.

### 보존과 제한

기존 OOXML의 표·그림·레이아웃·변경하지 않은 부분을 유지하며, 작은 교정은 기존 text run의 글자 서식을 가능한 한 유지한다. 문서 구조 재설계, 모든 혼합 서식, 머리말·꼬리말 수정, 추적 변경·수식 계산 엔진·모든 Office 문서에 대한 완전한 호환성을 보장하지 않는다. 특히 길거나 전면 교체한 문단은 일부 글자 서식이 달라질 수 있다고 안내한다.

매크로·전자서명·암호화·중복 ZIP 항목·과도한 압축 해제 크기를 거절한다. 셀 주소·외부 연결 수식과 잘못된 XML 문자를 검사한다. 긴 문단을 앞 2,000자만 보여 주고 전체를 대체하던 손실 위험을 없앴다. 모델이 읽지 못한 문단을 고치려 하면 적용하지 않는다. 새 수식은 열 때 재계산하도록 기존 계산 순서 참조도 정리한다.

실제 설치된 Word·Excel·PowerPoint에서 합성 문서의 **편집 전후 6개 파일을 열고 PDF로 내보냈다**. Word 1쪽씩, Excel 1쪽씩, PPT 2쪽씩의 총 8쪽을 PNG로 렌더링해 표·그림·강조·탭·줄바꿈·슬라이드 순서와 수정 범위를 비교했다. 셀 값·수식·병합 셀도 다시 읽었다. 외부 라이브러리는 검증용으로만 사용했고 ALEX의 필수 의존성을 늘리지 않았다. 제공 문서 렌더러는 LibreOffice 미설치로 실행할 수 없어 설치된 Microsoft Office와 번들 Poppler로 대체했다.

## 조사 근거의 실제 확인

공개 주제 “Python 3.11 unittest의 하위 폴더 발견과 skipped 결과 해석” 한 건을 기존 로컬 Strata로 조사했다. 첫 수집·보고는 35.88초, 검색 2회·서로 다른 본문 2개였지만 두 번째 질문의 근거 발췌가 부족했고 사용자가 요구한 짧은 답도 지키지 않았다.

원문 재수집 없이 같은 공개 자료로 발췌를 비교했다. 단순히 드문 단어를 우선하는 첫 후보는 버전별 조건을 놓쳐 오히려 잘못된 결론을 냈다. 그 후보의 결과를 보존하고 추가 수정했다. 최종 발췌는 `discover가` 같은 한글 조사를 영문 식별자와 분리하고 `3.11`, `__init__.py`를 그대로 유지하며 질문 항목을 고르게 포함한다. 작은 검색 한도에서도 부족한 근거를 위한 후속 검색 1회를 남긴다. 보고서 지시도 질문의 길이·형식을 우선하고 긴 원문을 반복 인용하지 않게 했다.

최종 같은 자료의 로컬 보고 재생성은 14.09초였고 두 질문의 핵심 결론을 공식 문서와 대조했다. 이 시간은 **보고 단계만**이며 첫 종단 35.88초와 속도 향상 수치로 비교하지 않는다. 한 주제의 수동 검토일 뿐 자동 선택 정확도·범용 사실 정확도·문장별 근거 일치가 입증된 것은 아니다. 실제 코딩 능력/Luna 동등성 측정도 아니다.

## 화면과 기록

코딩 화면을 다시 열면 마지막 독립 검사 보고를 복원하고 timeout·unverified도 주의 상태로 표시한다. 별도 가짜 서버와 독립 Edge 프로필에서 성공·미검증 표시, 모바일 폭, JS 오류 없음을 확인했다.

개발 PC의 `logs/codex-improvements-20261023/`에 원본·해시·재현·검사 결과·Office 렌더링·조사 원문·실패한 후보까지 보존한다. 비공개 설정·실제 대화·데이터·로그·Office 검증용 환경을 공개 저장소에 포함하지 않는다. 최종 검사 수와 실행 코드 지문·게시 커밋은 두 NEXT 맨 위의 최종 인계에 기록한다. `/self-check` 자동 실행은 계속 보류하며 모델·하드웨어 설정은 변경하지 않는다.

## 최종 검증 범위

- 공개 사본: 전체 1,709건 결과 `OK (skipped=13)`, Python 3.10 구문·의존성 감사, 라우터 83/83, 보안 13/13, alpha·beta smoke 통과. 이후 Office의 같은 이름 선택·중복 긍정 답 경계만 추가 수정해 **관련 8개를 다시 통과**시켰다. 마지막 경계 수정을 포함한 전체 1,710건을 다시 실행했다고 주장하지 않는다.
- 개발 원본: 전체 1,709건 중 기존 `jarvis/2dsoul.py`의 pygame 의존성 감사 1건 실패·5건 skip. 이 개인 파일과 검사 규칙은 변경하지 않았다. 공개 사본은 기존 배포 정책에 따라 해당 개인 파일을 포함하지 않는다.
- 실제 HTTP 채팅 → 편집 사본 artifact 등록 → 다운로드 → 편집 내용/첨부 원본 보존을 격리 서버에서 확인했다. wheel에 새 unittest 어댑터·Office 모듈·기존 OpenCode 라이선스가 포함되고, 설치 형태에서 별도 프로젝트를 검사·캐시하는 것도 확인했다.
- 실제 설치된 CLI의 긴 표준입력, Office 3종의 열기·렌더링, 가짜 서버 UI 검사는 각각 위의 별도 근거다. 필수 의존성을 설치하거나 대규모 모델 평가·새 모델 다운로드를 실행한 것은 아니다.
