## 우선순위와 실제 변경

### 1. 하네스 선택 상태에서 설정 저장 오류 — 수정 완료

`WebAppState.save_settings()`가 일꾼이 존재하면 OpenCodeWorker로 다시 만들었다. 새 HarnessWorker에는 `home`·`command` 속성이 없어 추론 수준 저장부터 `AttributeError`가 발생했다.

`jarvis/web.py`에서 OpenCodeWorker 인스턴스만 다시 만들게 수정했다. HarnessWorker는 같은 객체를 유지하며 기존 provider_getter로 교체된 코딩 provider를 따른다. GPU 반환 확인 콜백도 다시 연결된다.

- 임시 설정·가짜 provider로 수정 전 오류를 재현했다.
- 추론 수준 저장과 Strata→Ollama 전환을 각각 회귀 검사로 추가했다.
- 관련 `test_model_switch.py` 20개 통과. 사용자 실제 설정 파일을 바꾸어 시험하지 않았다.

### 2. 목표 테스트만 보고 종료하는 일꾼 — 독립 검사·재수정 구현

종료 처리 과제는 `test_imagegen.py`를 통과했지만 관련 `test_media_shutdown_contracts.py`의 poll/wait/kill/final_wait 예외 처리 하위 검사 4개를 남겼다. 버그를 심은 상태에서 이미 실패하던 관련 검사라 바깥 루프에서는 기존 실패로 취급했다.

`jarvis/harness/worker.py`의 작업 지시를 보강했다.

- grep과 필요한 구간 읽기부터 시작해 큰 파일·전체 테스트의 반복 실행을 줄인다.
- 명시된 테스트 외에도 변경 API를 가져오거나 사용하는 기존 테스트를 찾아 읽고 실행한다.
- 같은 변경 원인의 관련 실패는 수정 전부터 실패했더라도 범위 안에서 고친다. 무관한 환경·의존성 실패는 구분해 보고한다.
- 관련 검사까지 통과한 경우만 완료라고 말하고, 남은 실패는 명시한다.

지시 보강판의 실제 검증에서는 목표 78개·관련 종료 검사 2개가 모두 통과했다(일꾼 556.47초, 외부 재검사 제외). 이는 한 과제 1회 검증이며 전체 6과제 성공률이나 속도 향상 증거로 확대하지 않는다.

**후속 실제 동작 보강:** `verification.py`가 기존 테스트의 직접 import와 변경 함수·메서드 사용을 연결한다. 모델이 완료라고 답한 뒤 ALEX가 관련 테스트를 독립 실행한다. 실패하면 실제 출력으로 같은 대화에 한 번 재수정을 요청하고, 그래도 실패하거나 검사 결과가 불명확하면 성공 종료하지 않는다. 기존 테스트는 편집 권한과 원본 복원으로 보호한다. 같은 초에 같은 길이로 수정한 소스를 오래된 pyc로 검사하지 않도록 격리 복사본의 캐시도 제거한다. 전체 skip·0건 실행은 검증으로 인정하지 않는다.

`developer.py`는 독립 검사·재수정 결과를 회차 기록에 남기고, 최종 거부 진단도 다음 수정 회차로 전달한다. 단계 상한에 도달한 작업도 정상 완료와 구분해 실패로 반환한다.

직접 import와 함수 사용은 관련 테스트를 좁히는 휴리스틱이다. 동적 import·간접 의존성까지 완전한 지도는 아니며 바깥 전체 회귀 검사를 계속 사용한다. 적용 경로는 `/dev-auto`·`/build`의 HarnessWorker다. 별도 `/code` 세션은 권한·질문·되돌리기가 있는 CodingAgent 경로이며 이번 독립 검사 훅을 공유하지 않는다.

### 3. 긴 파일 탐색과 문맥 낭비 — 관련 시험 지도·400줄 읽기

작업 시작 때 수정 대상 모듈을 직접 가져오는 테스트 위치를 먼저 제공한다. 일꾼의 Read 도구는 한 번에 최대 400줄을 반환하며, 출력에 다음 offset을 안내해 이어 읽을 수 있다. 일반 코딩 세션의 기존 읽기 한도와 모델의 전체 문맥 설정은 유지한다. 실측 전 일반적인 속도 개선 비율을 주장하지 않는다.

1. **모델 호출 도중의 시간 한도 적용**: 현재 deadline은 모델 차례 사이에서 검사한다. 600초 검증은 종료 요약 호출이 오래 계속돼 자체 클라이언트를 중단했다. 사용자 취소·응답 스트림·소켓 대기를 포함한 시간 상한 강화를 후속 우선 항목으로 남긴다. 성공으로 집계하거나 중단 사실을 숨기지 않았다.
2. 6번 과제의 변이 위치를 현재 소스에 맞춘 별도 버전으로 복구한 뒤, 동일 문맥·출력 한도와 고정 소스에서 여러 회차 재평가한다. 기존 과제와 원본 기록은 보존한다.
3. 실패 출력의 API·위치를 시험 지도에서 더 우선 정렬한다. 관련 검사부터 실행하고 최종 전체 회귀는 바깥 루프가 수행하도록 유지한다.
