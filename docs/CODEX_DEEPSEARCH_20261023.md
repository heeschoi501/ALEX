## 최신 보강 — 명령어 없이 자동 선택

사용자가 '필요하면 스스로 딥서치를 해야지, 굳이 명령어로 하게 하면 안 된다'고 교정했다. 아래 초기 구현의 **명시적 요청 전용 조건을 해제**했다.

- 일반 질문 → 기존 대화. 간단한 최신 사실 → 기존 자동 웹 검색. 공개 정보의 복합 비교·여러 근거 조사는 자동 딥서치. 예: 'RTX 5080과 5090의 성능·가격·VRAM 비교', 'Windows 로컬 코딩 LLM의 성능·메모리·라이선스 비교'.
- 두 경로로 고른다. `automatic_request`가 공개 정보·비교·평가 항목/근거 요구를 함께 보고 직접 연결한다. 그 밖의 일반 대화에서도 로컬 모델이 기존 `web_search`의 선택 인수 `depth=deep`을 골라 같은 실행기로 넘긴다. 매 질문에 추가 분류 모델을 부르지는 않는다. 규칙은 모든 표현을 알아듣는 분류기가 아니며, 도구를 지원하지 않는 모델은 두 번째 경로를 쓰지 못한다.
- 도구 선택은 `ResearchRequested`로 코어에 전달하고 현재 생성 차례를 끝낸다. 수집 결과를 다른 모델 차례로 다시 요약하지 않고 원래 딥서치 보고서를 직접 돌려준다. 이 신호는 provider 장애/클라우드 fallback이 아니다. 검색 도중 심층 조사로 넘어갈 수 있으며 기존 단순 검색과 딥서치 각각의 횟수 상한은 유지한다.
- '검색 없이/하지 마'는 자동 검색·딥서치 도구와 웹 라우팅에서 우선한다. '짧게/간단히'는 자동 딥서치를 피한다. 딥서치만 하지 말라는 말은 간단 검색까지 막지 않는다. 로컬 파일·첨부·코딩 작업·현재 기계·불분명한 지시어를 공개 조사로 자동 보내지 않는다. 원래 질문과 검색어의 기존 민감정보 검사도 유지한다.
- 자동 진입 시 진행 안내와 '질문에 맞춰 자동 선택' 표시를 붙인다. 출처·취소·240초 기한은 같은 실행기를 사용한다. `/research`·`/deepsearch`는 원할 때 직접 지정하는 선택지로 유지한다. 실행에 필수인 명령어가 아니다.
- 로컬 모델에게도 필요하면 스스로 검색 깊이를 선택하고 사용자에게 검색 명령을 요구하지 않도록 안내한다. 실제 보고서를 쓴 모델의 잘림 상태를 사용해 코딩 모델에서 전환된 경우 이전 모델의 상태를 잘못 붙이지 않게 했다.

## 기존 구조와 변경

기존 `/search`와 일반 채팅의 검색 도구는 간단한 조회용이다. 상위 결과 중 본문 하나를 읽는 구조여서 여러 검색어·자료의 비교와 추가 확인을 맡는 별도 실행기가 없었다. 이 경로는 유지하고 `jarvis/research.py`를 더했다.

1. **호출**: 위 최신 보강대로 질문에 맞춰 자동 선택한다. 사용자가 직접 `딥서치로 주제를 비교해줘` / `주제 심층 조사해줘` / `/research 주제` / `/deepsearch 주제`로 지정할 수도 있다. 기능을 설명하거나 구현해 달라는 말은 조사 요청으로 가로채지 않는다. 명시적 요청의 주제가 없거나 '이거'뿐이면 구체적인 주제를 묻는다.
2. **계획**: 현재 로컬 일반 모델(실패하면 로컬 코딩 모델)에 최대 3개 검색어를 요청한다. JSON이 잘못됐거나 모델이 실패하면 원래 공개 주제를 검색한다. 대화 기록·기억·프로젝트 파일을 계획에 넣지 않는다.
3. **수집**: 기존 `WebReader`로 검색·본문을 읽는다. 각 검색의 첫 결과부터 번갈아 읽고, 후속 조사에 일부 본문·출처 예산을 남긴다. 사용자가 적은 공개 URL도 최대 3개 읽을 수 있다.
4. **추가 확인**: 부족한 근거와 다른 주장을 살피는 로컬 모델 단계가 한 번 있다. 검색어 하나를 더 받아 남은 범위에서 조사한다. 추가 검색 뒤에도 확인하지 못한 사항은 보고서에서 유보한다.
5. **보고**: 실제 자료 번호와 질문에 관련된 발췌를 로컬 모델에 전달한다. 앱이 실제 출처와 본문/요약 상태, 오류, 조회 시각을 붙인다. 미등록 번호와 주소는 걸러 표시한다. **본문 확보는 사실 검증이나 문장별 인용 일치 보장이 아니다.**

## 동작 범위와 안전 경계

- 기본 상한: 검색 4회, 서로 다른 본문 최대 6개, 출처 12개, 본문 요청 8회, 전체 240초. 로컬 생성·HTTP도 같은 기한을 받는다. 모델 단계 사이에 기존 뒤 작업의 대화 양보 지점을 부른다. `/bg /research 주제`로 기존 뒤 작업을 쓸 수 있다.
- 진행 단계가 기존 채팅 스트림에 나온다. 중단 시 새로운 요청을 멈추고 수집한 자료를 보존한다. 시간 한도에 도달한 결과는 부분 조사로 표시한다. HTTP 본문 대기는 해당 응답 소켓만 끊는다. DNS·헤더 대기는 기존 소켓 시간 제한까지 걸릴 수 있다.
- URL 정규화·리디렉션 합치기·동일 본문 해시로 중복을 줄인다. 동일 본문은 독립 근거 수에 포함하지 않는다. 동일 도메인 자료만 있거나 본문이 부족하면 한계를 표시한다. 별개 URL이라고 독립된 연구 결과임을 보장하지는 않는다.
- 기존 공개 주소/DNS/접속 소켓/리디렉션 SSRF 방어를 그대로 쓴다. 공개 웹 연결에 로컬 모델용 비보호 opener를 쓰지 않는다. DuckDuckGo 캐시·임시 차단 대기를 유지하며 우회하지 않는다.
- 기존 민감정보·로컬 경로 검사를 원래 주제와 모델이 만든 검색어에 적용한다. 원문은 외부 LLM에 보내지 않는다. 로컬 모델 실패를 이유로 클라우드를 호출하지 않는다. 민감정보 검사는 완벽한 DLP가 아니므로 비밀 자료를 조사 주제에 넣지 않는다.
- 본문과 검색 결과는 신뢰하지 않는 자료로 다룬다. 딥서치 보고서를 자동으로 '검증된 교훈'에 올리지 않는다. 저장하는 것은 기존 대화 한 쌍(요청·결과)이며 원문 페이지 별도 저장소는 만들지 않는다.
- 작은 문맥 예산에 너무 긴 주제는 수집 전에 나눠 요청하도록 안내한다. 큰 자료는 출처별로 예산을 나눠 관련 부분을 발췌한다.
- 실제 파일 이름과 수정 표현이 있어도 명시적 딥서치는 자연어 코딩 세션을 시작하지 않는다. 기존 일반 코딩·허락 흐름은 보존했다.
