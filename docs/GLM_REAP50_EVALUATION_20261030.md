# GLM-5.3-Flash REAP-50 Q23 시험과 제외 결정 — 2026-10-30

ALEX의 두 번째 로컬 모델 후보로 GLM-5.3-Flash REAP-50 Q23을 설치해 시험했다. 결론은 **제외**다.
한국어 출력이 모델 자체에서 깨지고, 생성 속도는 최선 설정에서도 약 16 tok/s여서 기본 모델 Qwen3.8-Flash-Next(약 60 tok/s)를 대신할 수 없다.
시험이 끝난 뒤 모델·엔진·ALEX 연결 코드를 모두 지웠다. 이 문서는 시험 결과만 남긴다.

시험 장비: RTX 5080 16GB, Ryzen 7 9800X3D(8코어), RAM 96GB DDR5-5600, Windows + WSL2(Ubuntu 22.04).
설치와 속도 조정은 Codex가, ALEX 연결·언어 진단·생성 경로 시험은 Claude가 했다.

## 1. 설치한 것

- 엔진: [lighttransport/Strata `glm53f` 브랜치 `fcf56cb`](https://github.com/lighttransport/Strata/blob/fcf56cbf46ad894c2e0e1a1ae8f82435e9cefa8a/docs/GLM53F_RELEASE.md). 기존 Strata(Qwen용)와 따로 설치했다.
- 모델: [`lte-ai/GLM-5.3-Flash-Strata-Q2Q3-Experts`](https://huggingface.co/lte-ai/GLM-5.3-Flash-Strata-Q2Q3-Experts/tree/0d0f578cb35e68ac1f65c31640e046d15883cbfa/reap50)의 `reap50/GLM-5.3-Flash-REAP50-Q23-FP8-assembled.gguf`.
  - 크기는 63.2GB이고, SHA256 은 `03d09db9…a1491401` 이다.
  - 288개 전문가 중 144개를 남기고 잘라 낸(REAP) 판이다.
- 포크 문서상 품질(FP8 원본 대비): perplexity +16.5%, KL 0.393, top-1 80.4%, HumanEval 154/164. 모두 영어·코드 기준이다.
- ALEX 연결: 설정 화면에서 Strata 모델을 Qwen↔GLM 으로 고르게 했다.
  - 같은 8080 포트에서 한 번에 하나만 돌았고, 바꿀 때 떠 있는 서버를 끄고 올렸다.
  - 시험 13개를 함께 만들었다. 제외하면서 이 코드도 지웠다.

## 2. 속도 조정 (Codex)

같은 모델·32K 문맥·CPU 7스레드·GPU 예산 12,288MiB 조건이다. 각 조건은 워밍업 1회를 빼고 3회 측정한 중앙값이다.

| 조건 | 입력 처리 tok/s | 생성 tok/s |
|---|---:|---:|
| 2K 입력 기준 | 248.77 | 12.84 |
| 입력 배치 2048 | 399.79 | 12.75 |
| 입력 배치 4096 | 402.98 | 12.61 |
| 배치 4096 + MTP 1단계 | 369.50 | 9.46 |
| 8K 입력, 배치 1024 | 248.03 | 12.34 |
| 8K 입력, 배치 4096·작업공간 2GiB | **583.38** | 12.14 |

- 긴 입력 처리는 2.35배 빨라졌다(8K 읽기 약 33초 → 14초). 생성 속도는 그대로였다.
- 모델을 미리 읽어 두는 설정은 첫 글자는 빨라졌지만 전체 대기가 길어져 채택하지 않았다.

## 3. 한국어가 깨지는 원인 (Claude)

**원인은 모델 자체다.** 템플릿과 추론 모드는 원인이 아니었다.

- **템플릿:** 서버는 모델 파일에 든 GLM 공식 템플릿을 그대로 쓴다. 생각을 끄면 `<|assistant|><think></think>` 로, 템플릿 자신의 형식과 같다.
- **같은 질문을 언어·추론 모드만 바꿔 물음** (온도 0):

| 경우 | 결과 |
|---|---|
| 영어, 생각 끔 | 정상 |
| 중국어, 생각 끔 | 약 150토큰 뒤 `（或）的` 반복 |
| 한국어, 생각 끔 | 첫 줄 뒤 `(앨)` 반복 |
| 한국어 + '한국어로만 답하라' 시스템 지시 | 중국어로 바뀐 뒤 반복 |
| 한국어, 생각 낮음 | 생각(영어)은 정상, 답은 `있지 있지 …` 반복 |
| 한국어, 생각 최대 | 생각 자체가 깨짐, 답 없음 |
| 영어 코드, 생각 낮음 | 정상, `</think>` 누출 없음 |

- **실제 코딩 과제** (ALEX 코딩 하네스, 격리 사본, `bisect_left` 버그 수정, 시험 6개):
  - 한국어 지시와 영어 지시 모두 6/6 으로 통과했다.
  - 한국어 지시의 마지막 보고문은 `6개 시험 전다 핓니다.` 처럼 깨졌다.
- **이유:** 포크가 남길 전문가를 고르고(REAP) 양자화 중요도를 정할 때 쓴 보정 자료는 그 저장소의 코드와 영어 문서뿐이다(`tools/glm_q2_corpus.py`).
  보정 자료에 없던 언어를 맡던 전문가가 먼저 잘린 것으로 본다. 공개 사례도 같은 방향이다.
  - [Kimi K3 REAP](https://huggingface.co/runrunway/Kimi-K3-REAP-224experts): 보정 99% 영어, 중국어가 한 토큰 반복
  - [GLM-4.7-Flash KGuard REAP](https://huggingface.co/buugiiiiii/GLM-4.7-Flash-KGuard-REAP-32E): 절반을 잘랐을 때 한국어 점수 68.8 → 51.2
  - [압축 기법 비교 연구](https://arxiv.org/pdf/2608.21693): 같은 압축률에서도 보정 자료에 따라 남는 능력이 달라짐

## 4. 생성 속도 최적화 시험 (Claude)

**측정 방법:**
- 같은 영어 질문 3개를 300토큰씩, 온도 0으로 생성했다. 질문 1은 서버를 띄운 직후 첫 요청이다.
- 답이 기준과 한 글자까지 같은지, 영어 설명·코드 답, ALEX 코딩 과제(한국어·영어 지시)를 함께 확인했다.
- 각 설정은 1회씩 측정했다. GPU 감시를 켜 두었다(빈 메모리 1.5GB 미만이거나 83℃ 이상이면 정지).

| 설정 | 생성 tok/s (질문 1·2·3) | 답이 기준과 같은가 | 코딩 한국어 / 영어 |
|---|---|---|---|
| 기준(Codex 조정 설정) | 9.94 · 12.36 · 12.49 | — | 시간 초과 / 47.0초 |
| 라우팅 근사 0.06만 | 8.88 · 9.46 · 11.5 | 같음(근사가 걸리지 않음) | 52.9 / 38.0초 |
| **단계 파이프라인** | **12.75 · 15.57 · 16.0** | **같음** | **43.6 / 35.2초** |
| 파이프라인 재측정 | 10.12 · 14.67 · 15.81 | 같음 | 44.1 / 35.3초 |
| 파이프라인 + 라우팅 근사 0.06 | 13.78 · 21.94 · 21.6 | 다름, 질문 2 반복 붕괴 | 40.4 / 33.1초 |
| 파이프라인 + MTP 1단계 | 11.82 · 12.61 · 13.99 | 같음 | 174.5 / 159.0초 |
| 파이프라인 + MTP 2단계 | 10.5 · 11.49 · 14.01 | 같음 | 93.2 / 149.1초 |
| 파이프라인 + Q8 생성 경로 | 9.9 · 17.09 · 16.09 | 다름, 영어 답 품질 저하 | 48.0 / 38.7초 |
| 파이프라인, 스레드 4 | 9.28 · 14.09 · 15.75 | 같음 | 41.0 / 41.6초 |
| 파이프라인, 스레드 6 | 8.88 · 15.2 · 15.89 | 같음 | 43.7 / 42.2초 |
| 파이프라인, 스레드 8 | 11.1 · 13.78 · 15.87 | 같음 | 296.8 / 35.3초 |
| 동시 적용: MTP1 + 근사 0.06 | 13.44 · 14.73 · 16.12 | 다름 | 93.1 / 148.9초 |
| 동시 적용: MTP1 + 근사 0.02 | 10.08 · 14.29 · 14.76 | 다름, 질문 2 반복 붕괴 | 시간 초과 / 163.4초 |
| 동시 적용: MTP2 + 근사 0.06 | 13.3 · 14.57 · 16.33 | 다름 | 119.8 / 117.1초 |
| 동시 적용: MTP2 + 근사 0.02 | 9.7 · 10.25 · 16.17 | 다름 | 132.0 / 156.6초 |

동시 적용은 모두 파이프라인 + Q8 + 스레드 8 위에 MTP·근사를 더한 것이다.

- **단계 파이프라인(`STRATA_GLM_STEP_PIPELINE=1`):** 답은 그대로이고 생성이 약 27% 빨라졌다. 처음 프로필에는 이것이 빠져 있었다.
  - 라우팅 근사와 GPU 전문가 캐시 자동 교체(`STRATA_GLM_TIER_ADAPT`)는 이 파이프라인이 있어야 동작한다. 그래서 근사만 켠 첫 시험은 아무 효과가 없었다.
- **라우팅 근사:** GPU에 올라간 전문가를 우선 고르게 하는 설정이다. 가장 빨랐지만(21.6 tok/s), 이미 약해진 모델에서 영어 답까지 반복으로 무너졌다.
- **MTP:** 짐작은 90–97% 맞았지만 느려졌다. 이 PC에서는 전문가 계산을 CPU가 맡아서, 짐작한 토큰마다 전문가를 따로 더 계산해야 하기 때문으로 본다. 코딩은 3–4배 느려졌다.
- **Q8 생성 경로:** 속도 차이는 오차 안이었고 답만 나빠졌다.
- **CPU 스레드:** 4–8개가 같은 속도였다. 생성 속도는 스레드 수에 묶여 있지 않았다.
- **같은 설정의 흔들림:** 기준 설정의 한국어 지시 과제는 한 번은 83초에 통과하고 한 번은 시간 초과였다. 모든 설정을 1회씩만 쟀으므로 작은 차이는 판단 근거로 쓰지 않는다.
- **자원:** 모든 시험에서 GPU 사용은 최대 14,526 / 16,303MiB, 66℃였다. 매번 서버를 정상 종료했다.

## 5. 결정

- 한국어는 설정으로 고칠 수 없다. 살리려면 한국어를 넣은 보정 자료로 다시 잘라야 하는데, 원본 전체 모델과 긴 파이프라인이 필요해 이 PC 범위를 넘는다.
- 최선 설정(파이프라인)의 약 16 tok/s는 Qwen의 약 1/4이다. 포크 개발자가 비슷한 장비에서 낸 최고치도 결과가 달라지는 설정으로 약 20 tok/s였다.
- 그래서 GLM 은 ALEX 후보에서 뺐다. 모델(63GB)·엔진·실행 도구·ALEX 연결 코드를 모두 지웠다. 기본 모델은 Qwen3.8-Flash-Next 그대로다.
