# ALEX 최신 결과 재검토·검증 개선 — 2026-10-04

사용자의 전체 인계와 첨부 보고서, 실제 평가 JSON, Claude의 21:00 인계를 대조했다. 이번 변경은 **놓친 기능과 잘못된 성공 판정을 잡는 평가·검사 개선**이다. 모델의 코딩 성공률이 상승했다는 새 실험 결과는 아니다.

## 1. 최신 결론

| 조건 | 엄격 성공 | 과제 시간 합계 |
|---|---:|---:|
| 과거 변경 과제 16K | 5/11 | 약 96분 |
| v2: 48K + API + 회귀 검사 | 9/11 | 189.0분 |
| 동일 v2 + 진단 근거 | 9/11 | 213.8분 |

두 v2 결과의 성공 과제 집합도 같다. 문서의 중간 5/6은 완료 결과로 대체해서 판단한다. 진단은 이 실험에서 추가 이득이 없고 약 13.1% 오래 걸렸다. 기본 꺼짐 유지가 타당하다. 모델 크기나 RAM만으로 설명할 수 없으며, 현재 장비에서 120B를 다시 비교하지 않는다.

Claude가 적용한 잔여 실패 기록·생성 중 취소 처리(제안 A)는 이미 존재한다. 이전 제안 복사본을 덮어쓰지 않았다. 추가 읽기 제안 B는 이번에 적용하지 않았다. 공개 도구 전체 비교가 취소되었으므로, 그 전체 비교 완료를 B의 무기한 선행 조건으로 삼을 필요도 없다. 남은 실제 실패가 필요한 읽기·검색 범위를 확인하는 근거가 되어야 한다.

## 2. Claude의 OpenCode 조사 재확인

- **전체 11과제 OpenCode 비교 취소**를 반영했다. 새 도구는 `--solver opencode`에서 선택된 과제가 정확히 하나일 때만 실행된다. 과제 미선택·여러 개 선택은 모델이나 스냅샷 생성 전에 거부한다.
- [OpenCode 이슈 #46506](https://github.com/anomalyco/opencode/issues/46506)은 실제로 열려 있다. macOS/M1·OpenCode 1.18.25·Ollama 0.32.14 사용자가 수분의 추가 지연을 보고했다. 현재 Windows/v1.18.34에서도 7배 느리다는 뜻은 아니며, 해결책이 확인된 자료도 아니다. reasoning 요청과 문맥 설정 차이가 함께 제시되어 있다. 따라서 ALEX 제공자 코드를 추측으로 바꾸지 않았다.
- [Qwen 공식 모델 카드](https://huggingface.co/Qwen/Qwen3.8-27B)는 도구 사용과 코딩 평가를 제공하지만, 여기의 특정 Q3 파일·5080·48K 조합 성능을 보증하지 않는다. 공개 성공 사례를 활용하되 ALEX의 9/11을 대신하는 수치로 쓰지 않는다.
- Q3 가중치가 약 13GB여도 실행 시 KV 캐시·추론 버퍼·다른 GPU 사용량이 더해진다. **48K에서도 16GB 완전 적재 및 46 tok/s가 확정된 것은 아니다.** [Ollama 문맥 안내](https://docs.ollama.com/context-length), [메모리·KV FAQ](https://docs.ollama.com/faq)를 함께 참고한다. Q3는 Claude 인계대로 사용자 결정 대기이며 다운로드·서버 환경·실사용 설정을 변경하지 않았다.

## 3. 적용한 코드

### A. 불완전한 성공 판정을 차단

`logs/probe/coding_agent_eval.py`:

1. 주입 전 **해당 합격 테스트가 원본에서 통과하는지** 검사한다. 원래 실패하면 버그 감지로 집계하지 않고 이유를 결과에 남긴다.
2. 기존 앱의 `_suite_digest` / `_suite_report`를 재사용한다. 0개 검사·전부 skip·사용법 오류·완료 요약 불명은 미검증 예외로 중단한다. subTest 인자와 unexpected success를 실패 ID에서 보존한다.
3. OpenCode의 시간 초과·비정상 종료·대상 파일 삭제·허용 파일 밖 최종 변경은 성공에서 제외한다. 이전의 '테스트를 원복한 뒤 성공 가능' 방식 대신 위반 자체를 기록한다.
4. `--out` 지정 시 OpenCode 전체 이벤트 로그를 `<결과 JSON>.evidence/`에 보존한다. 임시 폴더 삭제 후 꼬리 1,500자만 남던 문제를 줄였다. 결과에는 실제 OpenCode 모델 이름과 로그 경로도 기록한다.
5. 건너뛴 과제도 즉시 저장한다. 단일 과제의 기준선 실패만 발생해도 결과 파일이 남는다.

제약: 파일 복사본은 OS 보안 샌드박스가 아니다. 사후 변경 비교는 잠시 수정했다 되돌린 파일·외부 경로 접근·네트워크를 차단하거나 증명하지 않는다. 실제 OpenCode 실행은 하지 않았고, 외부 접속 차단도 검증하지 않았다. 검사 로그가 읽히지 않는 경우 현재 행의 상세 복구 기록은 추가 개선 여지가 있다.

### B. 목표의 일부만 복원해도 통과하던 검사 보강

- 합격 검사에 쉼표로 여러 테스트 파일을 지정할 수 있게 평가 도구와 정적 preflight를 맞췄다. ALEX `/dev-start`의 기존 다중 검사 기능을 그대로 활용한다. OpenCode 프롬프트에도 검사 명령을 모두 나열한다.
- 새 과제 파일: `logs/probe/history_tasks_contracts_v3_20261004.json`.
  - outcomes 과제: `test_developer.py`에 `test_insights.py`를 추가. `/dev-outcomes`만 복원하고 `/dev-learn`·`/dev-insights`를 남기는 수정을 합격 검사에서 잡는다.
  - GPU 모델 설정 과제: `test_ram_offload.py`에 `test_config.py`를 추가. 환경변수 경로 누락을 확인한다.
  - 옛 12개 정의 중 현재 코드와 두 번째 앵커가 맞지 않는 `hist_codex-backup-20261003-status_developer_test_developer`는 새 버전에서 제외했다. 기존 정의 및 평가 파일은 보존했다. 최종 **11개 모두 정적 앵커·문법 검사 통과**. 실제 변이 감지·LLM 풀이 성공은 아직 측정하지 않았다.

- `tests/test_config.py`: GPU 층 제한 모델의 환경변수 읽기·공백 제거·로컬 파일 및 명시적 빈 환경변수 우선순위 검사.
