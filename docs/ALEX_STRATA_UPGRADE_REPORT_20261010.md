# ALEX 업그레이드 결과 보고서 — Strata 로 Qwen3.8-Flash-Next(125B MoE) 연결

작성: 2026-10-10, claude (Codex 검토 결과 포함). 사용자 요청 "strata를 사용해서 alex를 업그레이드해보고 싶은데" → "전부실행해" → "결과보고서도 작성해주고".

## 1. 결론

**ALEX 의 기본 모델을 Qwen3.8-27B(Ollama)에서 Qwen3.8-Flash-Next 125B(Strata)로 바꿨고, 바꾼 쪽이 낫다.**

- 같은 16GB 그래픽카드에서 **더 똑똑하고(공식 에이전트 코딩 점수 58.7 vs 42.2) 더 빠르다(초당 59~76토큰 vs 52~65)**.
- 자동 코딩 과제 6개 중 **강화된 검사 기준으로 5개를 제대로 고쳤다.** 나머지 1개(영상 요청 라우팅)는 다른 기능을 깨뜨렸고, 전체 회귀 검사가 그것을 잡아냈다.
- 대가: Strata 가 켜져 있는 동안 GPU 메모리 약 15GB 와 RAM 약 60GB 를 계속 차지한다. 게임·그림 생성 전에는 `/unload`.
- 이번에 확인한 더 중요한 사실: **"테스트 통과"는 "제대로 고침"이 아니다.** 첫 평가에서 6/6 통과였지만 그중 3개는 테스트가 보지 않는 곳에서 보호 장치를 빠뜨렸다.
  검사를 보강하자 같은 모델이 그 빈틈까지 메운 수정을 냈다. 자동 수정은 제안까지만 하고 적용은 사용자 승인으로 두는 지금 구조가 맞다.

## 2. 무엇이 바뀌었나

| 항목 | 전 | 후 |
|---|---|---|
| 대화·코딩 모델 | Qwen3.8-27B (3비트, Ollama) | Qwen3.8-Flash-Next 125B MoE (IQ3_S, Strata 0.1.41) |
| 문맥 | 16,384 토큰 | 65,536 토큰 |
| 코딩 일꾼(OpenCode) | Ollama 27B (32K) | Strata 125B (64K) |
| 자동 수정 판정 | 합격 테스트 | 합격 테스트 + 전체 회귀 검사 + 보호 계약 검사 |
| ALEX 시작 | Ollama 준비 | Strata 자동 시작(이 PC 실측 21초) |

설정: `jarvis.local.json` 의 `local_backend: "strata"`(되돌리기 = `"ollama"` 로 바꾸고 재시작, 이전 설정 백업 `jarvis.local.json.bak-20261010-strata`).
설계 기록: ADR-086(Strata 연결), ADR-085(LoRA 학습 데이터). Strata 설치 `C:\ALEX\tools\strata`, 모델 `C:\ALEX\tools\Strata-data`(84GB).

### MoE 라서 가능한 것

Qwen3.8-Flash-Next 는 전체 125B 이지만 층마다 전문가 512개 중 11개만 써서 한 단어에 약 6B 만 계산한다. Strata 는 전문가 전부(약 50GB)를 RAM 에 두고 자주 쓰는
전문가만 그래픽카드에 올려, 16GB 카드로 125B 를 돌린다(RAM 96GB 라 가장 좋은 IQ3_S 크기를 쓸 수 있다 — 공개 시험에서 원본과 같은 점수).

비교(이전 실측): 27B 3비트 전부 GPU 초당 52~65토큰, 문맥 16K.

## 4. 자동 코딩 평가 (/dev-auto, 실제 ALEX 버그를 되살려 고치게 하는 과제)

원래 과제 11개 중 5개는 과제를 만든 뒤 코드가 바뀌어 버그를 심을 자리가 없어져 평가할 수 없었다(평가 도구가 멈추던 것을 건너뛰게 고침). 남은 6개:

| 과제 | 1차(기존 기준) | Codex 의미 검토 | 2차(보호 계약 검사 포함) |
|---|---|---|---|
| 묶음 적용 뒤 개발 상태 갱신 | 통과 809초 | 원본과 동일 | **통과** 885초(원본과 동일) |
| 모델별 GPU 층 설정 | 통과 343초 | 내용 같음 | **통과** 339초 |
| 작업 기록·교훈 명령 연결 | 통과 902초 | 의도대로 | **통과** 866초 |
| 개발 작업 상태 유지 | 통과 809초 | ❌ 중단 복구 때 상태 표시 누락 | **통과** 1,588초(3회 고쳐 씀) |
| 그림 엔진 종료 | 통과 494초 | ❌ 일부 실패 경로 오류 누락 | **통과** 523초 |
| 영상 요청 라우팅 | 통과 672초 | ❌ "이 그림으로 영상" 요청이 그림으로 감 | ❌ **실패** 726초 — 합격 테스트는 통과, 보호 검사 5건 깨뜨림(같은 실수 반복) |

- 1차는 6/6 통과였지만 Codex 가 추가 검사(과제마다 2개씩)를 만들어 보니 3개가 보호를 빠뜨렸다 — 그 수정들은 실제 코드에 넣지 않았다.
- 2차는 그 검사를 전체 검사에 넣은 상태에서 다시 풀게 했다. 판정 조건: 버그 감지 · 합격 테스트 통과 · 전체 검사 종료 코드 0 · 새로 깨진 테스트 0.
- **2차 결과: 5/6** (합계 4,928초 ≈ 82분). 1차에서 빠뜨렸던 두 과제(개발 상태·그림 엔진)는 검사가 생기자 빈틈까지 메운 수정을 냈다.
- 영상 라우팅은 두 번 모두 '그림 판정을 영상보다 먼저' 하는 같은 실수를 했다. 이번에는 회귀 검사가 "이 그림으로 영상 만들어줘" 등 5가지 요청이
  깨진 것을 잡아 **실패로 판정**했다 — 실제 /dev-auto 였다면 이 수정은 '검증됨'으로 제안되지 않는다. 보호 장치가 의도대로 동작했다.

### 27B 와 비교 (참고)

| 기록 | 같은 6개 과제 |
|---|---|
| Strata 125B (오늘, 강화 기준) | 5/6 |
| 27B 최고 설정(10/4, v2-best) | 5/6 |
| 27B 다른 설정(10/4, ctx16k) | 3/6 |

27B 기록은 예전 코드·예전 수정 방식(오픈코드 이전)·강화 전 검사라 **같은 조건의 비교가 아니다.** 시간 합계는 Strata 약 67분(1차) vs 27B 최고 설정 약 88분.

## 5. 함께 한 일

- **Strata 설치:** 두 번째 모델 파일(28.8GB)은 설치 프로그램의 단일 연결이 초당 2~7MB 라 Hugging Face 병렬 다운로드(초당 40MB)로 받아 SHA-256 을 대조했다.
  GPU 메모리 2GB 를 비우도록 설정(`--vram-reserve-mib 2048`, 이 카드가 화면도 맡기 때문).
- **ALEX 코드(claude):** `StrataProvider`(OpenAI 호환 스트림·생각 상한·도구 호출·문맥 초과·중단), 설정 `local_backend`·`strata_*`(이 PC 주소만), 그림·`/unload` 의
  GPU 비우기, 오픈코드 일꾼 연결, 런처 자동 시작. 새 검사 16개.
- **보완(Codex):** Strata 만 준비하는 런처 경로, '모델 내림' 확인 엄격화, 설정 파일 선택, 보호 계약 검사 6개, 실사용 설정에서 전체 회귀 검사 켬. 전체 1176개 통과.
- **ALEX 가 안 켜지던 문제:** 바탕 화면(OneDrive)의 9/25 옛 사본이 실행돼 자기 Ollama 로 자리를 차지했다 → 옛 사본 삭제, 바탕 화면 `ALEX` 바로가기를 진짜 ALEX 로.
- **GitHub 공개(포트폴리오):** https://github.com/heeschoi501/ALEX — 이미지·영상 생성·개인 데이터·인계 메모 제외, 사용자 이름 제거. 갱신은 `alex-publish/prepare_publish.py`.

## 6. 주의와 남은 일

- Strata 는 개인 개발자 프로젝트(MIT, 매일 새 버전)다. 업데이트는 `UPDATE.bat` 로 하되 ALEX 쪽 검사를 다시 돌린다.
- Strata 문서에 NVIDIA 드라이버 리셋 사례가 있다. 이 PC 는 GPU 가 꺼졌던 기록이 있어 긴 GPU 작업은 사용자가 있을 때만 한다(오늘 감시 중 경고 0건).
- Strata 는 요청을 한 번에 하나씩 처리한다 — 자동 코딩 중에는 대화 답이 늦게 시작할 수 있다.
- 남은 결정: LoRA 학습 데이터 승인(묶음 20261005-b·c), OpenCode 직접 사용 방식(바탕 화면 실행 파일 / OpenCode Desktop),
  XREAL Aura 를 ALEX 화면으로 쓰는 원격 접속.
