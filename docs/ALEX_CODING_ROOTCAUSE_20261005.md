사용자: "테트리스가 문제가 아니라 다른 걸 만들더라도 이럴 거라는 거 아니야?", "둘 다 똑같은데… 코드 자체가 문제인지를 봐야지".

ALEX 코드의 잘못은 그 코드를 실행해 보지 않고 넘기는 구조와, 고치는 과정(모델 바뀜·문맥 참)이다.** 그 구조를 고쳤다.

## 2. ALEX 프롬프트가 원인인가 — 같은 모델·같은 옵션 A/B (`logs/claude-fixes-20261005/prompt-ab/`)

"파이썬 코드로 테트리스 게임 만들어줘", 문맥 16K·출력 8192·생각 켬, Ollama 직접 호출. 채점은 `logs/probe/claude_grade_tetris_20261005.py`
(코드 블록 추출 → 화면 없이 5초 실행 → 회전표·회전 함수/메서드 4번 돌려 모양 유지 검사). 채점기는 1~3차 실제 코드로 먼저 검증했다(손 검사와 일치).

- A: ALEX가 실제로 보내는 메시지 그대로(시스템 문구 2,357자 + 코딩 지시 + 장기 메모 + 질문). 재구성: `logs/probe/claude_dump_prompt_20261005.py` → `tetris-prompt.json`
- B: A에서 코딩 지시의 "추론은 짧게 한다…" 블록만 뺌(ADR-046. **qwen3:8b 로만 잰 지시**이고 "모델을 바꾸면 다시 재야 한다"고 적혀 있었는데 27B에서 잰 적이 없었다)
- C: ALEX 시스템 문구 없이 질문만

죽는 이유는 화면 없는 실행 때문이 아니라 실제 버그다: 속성을 만들기 전에 씀(`next_kind`), None 블록을 그림, 잘못된 색 값, 이름 가림(`'int' object is not callable`).
**같은 모델 안에서는 팔마다 같은 비율로 틀린다 → ALEX 프롬프트는 원인이 아니다.** "짧게 생각" 지시를 빼도 나아지지 않았으므로 그대로 둔다(근거 없이 바꾸지 않음).
**모델 차이는 크다:** 한 번에 제대로 도는 코드(시작 OK + 회전 OK) Q3 3/9 대 Q4 4/4(정확 검정 한쪽 p≈0.05). 시간은 Q3 29~46초, Q4 181~259초.
n 이 작아 작은 차이는 가려낼 수 없다. 오늘 Q4 가 틀린 3차 코드는 Q3 의 잘못된 진단을 대화 기록에서 따른 결과였다(1절).

## 3. 그래서 진짜 원인 — 어떤 프로그램이든 똑같이 생기는 구조 문제

1. **실행을 안 한다.** 한 번에 써서 넘긴다. 위 A/B 처럼 2/3 이 시작도 못 하는 코드가 그대로 사용자에게 간다.
2. **버그를 말해도 추측으로 고친다.** 실행해서 확인하지 않으니 "고쳤다"며 또 틀리고, 멀쩡한 곳을 원인으로 짚는다.
3. **파일을 직접 못 고친다.** "이 블록을 교체하세요" 안내뿐 — 반영이 빠지면 확인도 안 된다.
4. **코딩 대화 중에 모델이 바뀐다.** 코딩 단어 없는 후속 질문이 대화용 모델로 갔다.
5. **코드가 대화 기록에 쌓여 문맥이 찬다.** 후속 두세 번이면 생각이 답 자리까지 먹고 답이 없다.

## 4. 고친 것 (모두 검사 통과, 아래 6절)

1. **만들기 루프** `jarvis/build_loop.py` (설정 `coding_build_loop_enabled`, 기본 켬):
   "~ 만들어줘"(만들기 말 + 게임·프로그램·코드·스크립트 등)는 코딩 모델이 작업 폴더 `data/builds/<시각>-<세션>` 에
   `write_file`·`edit_file`·`read_file`·`run_python`·`finish` 도구로 직접 쓰고, **검사 파일(test_*.py)을 실행해 통과(종료 코드 0)해야만 끝낸다**
   (통과 전 finish 는 거절, 통과 뒤 고치면 다시 통과해야 함). 최대 16번 호출·25분. 후속 "고쳐줘/안 돼/추가해"는 **같은 작업 폴더에서 이어서** 고친다.
   답에는 검사 결과·파일 위치·실행할 파일 코드가 나온다.
   - 공개 자료: Harness Engineering(arXiv 2609.00006) — 11개 코딩 에이전트 모두 직접 짠 단순 반복 루프, 도구는 적고 굵게, 출력은 잘라서,
     끝내기 전 검증(verify-on-stop), 파일 수정은 찾아-바꾸기. 그 90줄 최소 뼈대를 ALEX 안전장치 안에 둔 것.
   - 안전: 작업 폴더 밖 경로·확장자 거부, 실행 전 정적 검사(subprocess·socket·shutil·ctypes·winreg·urllib/requests·os.remove/system 등,
     절대경로 open), 셸 없이 20초·출력 3,000자 제한(`developer._run_bounded` 재사용, 화면 없는 SDL). **운영체제 수준 격리는 아니다.**
   - 문맥: 파일 전체 내용은 대화에 다시 싣지 않고(“N자 — 파일에 반영됨”), 오래된 도구 출력은 줄인다.
   - 설명·방법 질문("설명해줘", "어떻게 만드는지 알려줘")은 예전처럼 글로 답한다.
2. **코딩 대화의 후속 질문은 코딩 모델로**(`core.handle`): 같은 세션 바로 앞이 코딩이었거나 코드 블록을 답했으면 `LOCAL_CODER`.
3. **생각이 답 자리까지 먹으면 생각 없이 다시**: 스트리밍 중 생각이 상한(출력 한도의 2/3, 문맥의 남은 자리 고려)을 넘으면 끊고(`ThinkingTooLong`),
   대화 경로에서 한 번 생각 없이 다시 부른다. 답 끝에 "[생각이 길어져 … 생각 없이 바로 답했습니다.]". 그래도 안 되면 예전 "/new" 안내.
