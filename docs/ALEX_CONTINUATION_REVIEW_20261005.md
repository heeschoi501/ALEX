# ALEX 최신 코딩 에이전트 변경 검토와 후속 보완

대상: Claude의 2026-10-05 10:50 인계 이후. 사용자의 “지금 작업 이어서 해줘” 요청으로 재개.

## 이어받은 상태

- 채팅 코딩은 코드 답변과 임시 폴더 실행 확인을 제공한다. `/build`는 파일 작성, `/dev-auto`는 기존 프로젝트의 수정안과 승인 절차를 담당한다.
- OpenCode가 코딩 일꾼이고 ALEX가 검사·범위·승인을 판단한다. Claude 기록의 v3 한 과제 통과는 범용 코딩 성능의 증거로 확대하지 않는다.
- 기존 전체 회귀 검사는 파일별 병렬 실행으로 약197초에서 약61초로 줄었다. 릴리스 스크립트에는 이 실행기가 아직 연결되지 않았다.
- 사용자 요청으로 1.5GiB 강제 예약을 제거한 상태를 유지한다. 반환 확인은 계속 적용한다.

## 발견한 문제와 수정 방향

### 1. OpenCode의 GPU 전환 보호 누락

기존 반환 확인은 `OllamaProvider`의 HTTP 요청에 연결돼 있었다. OpenCode는 별도 프로세스에서 Ollama `/v1`을 직접 호출하므로 이 확인을 우회했다. Worker 시작 전에 동일한 반환 확인을 연결해 `/dev-auto`와 `/build` 모두 검사하도록 보완한다. 실패하면 프로세스를 시작하지 않고 기존 실패 처리로 돌린다. 이는 ALEX 내부 경로의 보호이며 외부 프로그램 전체의 GPU 상호 배제를 보장하지 않는다.

### 2. 병렬 회귀 검사의 누락과 시간 제한

- 각 파일을 별도 discovery 패턴으로 실행하면 프로젝트의 `load_tests` 훅이 받는 패턴도 바뀐다. CPU 재현 프로젝트에서 직렬은 실제 실패를 찾았지만 기존 병렬은 그 검사를 빼고 통과했다. 훅의 정의·참조가 감지되거나 읽기/구문 확인이 안 되면 기존 직렬 discovery를 유지한다. 하위 테스트 패키지 fallback도 유지한다.
- 전체가0개 또는 모두skip이면 성공 종료 코드로 합치지 않는다. 실패 ID·완료 요약·ResourceWarning 검사는 계속 유지한다.
- 파일마다 전체 제한을 다시 시작하지 않고 대기 시간을 포함한 공통 제한을 적용한다.
- 훅을 문자열/주석에서 언급하는 것만으로 직렬로 바꾸지는 않는다. 동적으로 만들어지는 임의의 훅까지 완전히 해석하는 기능은 아니다.

### 3. OpenCode 결과의 완료 판정

`/dev-auto`는 Worker가 비정상 종료하면 그 회차 변경을 채택하지 않는다. `/build`는 시간 초과·비정상 종료·작성 거절·재검사 도중 소스 변경을 완료로 처리하지 않는다. 실패 답변은 실패 상태로 남겨 학습 성공으로 오인하지 않게 한다. Worker가 스스로 작성한 테스트는 요구사항의 독립된 정답 기준이 아니므로, 통과는 실행한 검사에 한정한다.

### 4. 릴리스 검사에도 검증된 실행기 재사용

`scripts/run_suite.py`가 `/dev-auto`와 같은 bounded suite runner를 호출한다. `scripts/verify_release.py`는 이를 사용하고, `--test-workers 1`로 원래 직렬 discovery를 선택할 수 있다. 문법·의존성·라우팅·보안·alpha/beta smoke 검사는 기존 절차를 유지한다. 하위 Python 프로세스도 UTF-8로 로그를 쓰도록 고정해 Windows 한글 출력 실패를 방지한다. 0개 검사나 실패를 CLI 종료 코드0으로 바꾸지 않는다.

## 남아 있는 확인

- 실제 `/dev-auto` 한 작업의 최종 소요 시간은 이번 CPU 검사로 측정되지 않는다. Claude의 기존42초 Worker/444초 전체 결과와 새 CPU 회귀 검사 시간을 직접 혼합하지 않는다.
- 실제 GPU 화면 꺼짐 해결 여부는 여전히 별도 확인 대상이다. 예약을 다시 도입하거나 OOM 한계 시험을 시작하지 않는다.
- 실행 확인은 프로그램의 의미상 정확성을 증명하지 않는다. 회전·상태 전이·파일 동작 등의 합격 기준을 독립적으로 추가해야 한다.
