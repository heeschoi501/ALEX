# ALEX 평가·현재 상태·하드웨어 판단 종합 정리

작성: 2026-10-04, Codex. 평가 집계 기준: **2026-10-04 14:24:16 KST에 읽기 복사한 JSON**.
범위: 현재 기능, 코딩 에이전트 평가, 최근 수정·검증, 모델·문맥·메모리 논의, 다음 확인 사항.
이 문서 작성 중 모델 호출·새 평가·앱 재시작·소스 및 설정 변경은 하지 않았다. 진행 중 평가의 이후 결과는 여기에 자동 반영되지 않는다.

## 1. 지금 가장 중요한 결론

- ALEX는 **로컬 모델에 파일 읽기·수정안·격리 실행·테스트 피드백·사용자 승인·작업 기록을 붙인 개인 AI 시스템**이다. 현재 가장 강화하려는 부분은 코딩 에이전트다.
- 27B의 쉬운 변이 평가 **15/16**, 어려운 변이 **9/11**은 확인됐다. 이 숫자를 일반 프로젝트 개발 성공률이나 Claude Code 수준의 증거로 해석하면 안 된다.
- 과거 실패 5개에서 **16K 0/5 → 48K 3/5 → 48K+API 요약 4/5**가 관찰됐다. 마지막 4개 중 1개는 증상만 우회한 수정이다. 더 넓은 문맥과 파일 밖 API 정보가 함께 중요했다.
- 최신 과거 변경 과제 기준선은 **11개 중 엄격 성공 5개**다. 개선판은 **완료된 6개 중 5개**이며 아직 전체 결과가 아니다. 진단 근거 추가의 효과는 후속 비교를 기다려야 한다.
- 큰 메모리는 더 큰 모델·긴 문맥·적은 CPU 오프로딩을 가능하게 한다. 그러나 **같은 모델·같은 문맥을 그대로 쓰면서 RAM만 늘린다고 정확도가 저절로 올라가지는 않는다**. 120/125B의 ALEX 코딩 우위와 Mac Studio 256GB의 구매 효과는 아직 직접 입증되지 않았다.

## 3. 평가 숫자를 읽는 기준

이 문서의 **엄격 성공(strict)** 은 저장된 결과에서 다음 네 조건이 모두 성립한 행이다.

1. 원래 버그가 검출됨: `bug_detected == true`.
2. 지정 합격 기준을 통과함: `acceptance_passed == true`.
3. 전체 검사 종료 코드가 0임: `suite_exit == 0`.
4. 새로운 실패가 없음: `new_failures == []`.

이것도 테스트가 놓친 의미상 오류를 보증하지 않는다. **합격 테스트 통과 / 엄격 성공 / 명세상 올바른 수정 / 사용자 적용**은 서로 다른 상태다. 특히 기준 소스에 이미 실패가 있는 향후 실험은 `전체 검사 0`과 `새 회귀 없음`을 별도 기록해야 한다.

평가 묶음끼리는 난이도·중복·소스·설정이 다르므로 분자·분모를 합쳐 “전체 정확도”를 만들지 않는다. 과거 쉬운 평가 16행에는 중복 ID 문제가 기록되어 있으므로 15/16은 **결과 행 기준**이며 독립적인 16개 사례라고 단정하지 않는다.

### 4.1 긴 문맥과 API 요약이 바꾼 것

| 조건 | 과거 실패 5개의 엄격 성공 | 의미상 검토 | 전체 소요 시간 기록 |
|---|---:|---|---:|
| 원래 16K | 0/5 | 기존 평가에서 모두 실패한 과제 선택 | 별도 동일 5개 실행 시간 집계 없음 |
| 16K+API | 2/5 | 작은 문맥을 API 정보로 보완 | 약 60분 |
| 48K | 3/5 | 제대로 복원 2 + 우회 1 | 약 110분 |
| 48K+API | 4/5 | 제대로 복원 3 + 우회 1 | 약 75분 |

- 큰 `core.py`의 발췌 밖 정보를 볼 수 있게 되면서, 존재하지 않는 기능을 지어내거나 엉뚱한 부분을 고치는 실패가 줄었다.
- `ask_file_local` 과제는 파일 밖 `tools.py`의 실제 `run(path=...)` API를 알아야 했다. **긴 문맥만으로 실패했던 것을 API 요약을 붙여 첫 수정에 복원**했다.
- `core 1679`는 분기를 삭제하고 호출부에서 다시 자르는 방식으로 시험을 통과했다. 이를 “원래 로직을 정확히 이해해 복구했다”로 세면 안 된다.
- `remote 151`은 48K+API에서도 실패했다. 실패 조건·멀리 떨어진 테스트 준비 코드가 더 필요한 사례다.
- 16K→48K 비교에는 GPU 층 수·입력 예산 등 설정 변화가 포함되고, 오래된 기준선과 실행 시점도 다르다. **관찰된 개선은 사실이지만 RAM 용량 하나만의 효과를 분리한 실험은 아니다.**

### 4.2 교훈은 현재 성공률을 올리지 못했다

쉬운 15/16과 어려운 9/11은 교훈 on/off에서 동일했다. 일부 회차가 줄거나 원본과 같은 수정이 늘어난 관찰은 있지만, 이를 새 문제 해결 능력 향상으로 표현하지 않는다. 잘못 일반화한 교훈이나 테스트에만 맞춘 규칙이 답을 악화시킬 위험도 있다. 코딩 절차 교훈은 기본 꺼짐을 유지하며 별도 검증 대상으로 본다. 근거: [PERFORMANCE 31](../PERFORMANCE.md), [교훈 분석](CODEX_TRAIN_INSIGHTS_ANALYSIS_20260930.md).

## 5. 진행 중인 최신 평가 — 완료 결과와 구분

Claude 인계 기준 대기열 7은 **16K 기준선 재개 → v2 최선 설정 → 같은 v2+진단 근거** 순서다. 실행 스크립트는 `logs/probe/claude_eval_queue7_20261004.sh`. 이번 작업에서는 프로세스·GPU·Ollama를 조작하지 않았다.

14:24:16 고정 사본에서 확인된 상태:

| 단계 | 관찰된 결과 | 상태 |
|---|---|---|
| 과거 변경 16K 기준선 | 합본 11행, 엄격 **5/11**, 합격 7/11 | 완료 |
| v2 최선 | 6행, 엄격 **5/6**, 합격 6/6 | **부분 결과**, 공통 평가 11개를 계획 |
| v2+진단 근거 | 대응 JSON 없음 | 결과 미확인. 미실행/진행 여부를 파일 부재만으로 확정하지 않음 |

v2에서 끝난 **동일한 6개 ID**에 한정하면 기준선 엄격 성공 2/6 → v2 5/6이다. 이는 중간 관찰이며, 남은 과제를 제외한 선택 효과와 여러 코드·설정 변경이 함께 들어 있다. **진단 기능 단독 효과나 최종 11개 성공률로 보고하지 않는다.**

v2 manifest(`caf688c18c6d579a`)의 조건:

- 모델 `qwen3.8:27b`, think 켬, 일반 경로 16,384 문맥·GPU 54층·기본 출력 6,144.
- 묶음 코딩 경로 **49,152 문맥·GPU 48층·입력 글자 예산 140,000**.
- API 요약 켬, 전체 회귀 검사 켬, 독립 풀이 1, 진단 근거 끔.
- 얼린 소스 `C:\ALEX\eval-frozen-20261004`, source hash `fba4031b39bbdb996f68b6a087994d312eb12a5d9aefd2e7b709d5d48b0e7ca6`.

manifest에 일반 `num_ctx=16384`와 코딩 `coding_num_ctx=49152`가 함께 있다. **이 실험 전체를 “16K 코딩”이라고 읽으면 잘못이다.** 후속 진단 켬/끔 비교는 같은 소스·모델·과제·설정에서 해당 플래그만 달라졌는지 manifest를 확인한 뒤 판단한다.

## 7. 실사용 설정과 평가 설정은 다르다

현재 `jarvis.local.json`의 관련 키만 읽었다. 인증정보 등 전체 설정은 증거 파일에 복사하지 않았다.

| 항목 | 로컬 파일 값 또는 기본값 | 해석 |
|---|---|---|
| 일반·코딩 모델 | `gpt-oss:20b` / `gpt-oss:20b` | 비데스크톱 모델 항목 |
| 데스크톱 일반·코딩 모델 | **`qwen3.8:27b` / `qwen3.8:27b`** | 자동 프로파일 선택 켬 |
| 문맥 | 전역 8,192 / 데스크톱 **16,384** | 48K가 실사용 기본 설정에 적용됐다고 보면 안 됨 |
| 출력 상한 | 로컬·데스크톱 **6,144** | 장문 코딩 경로의 동적 예산은 별도 |
| GPU 층 | 0, 모델 제한 빈 값 | 로컬 설정은 Ollama 자동 배치 |
| 코딩 교훈·API 요약 | false / false | 구현된 기능도 실사용 파일에서는 꺼짐 |
| 긴 코딩 문맥·GPU·글자 예산 | override 없음, 코드 기본 0 | 대화 설정을 따르는 기본 동작 |
| 독립 풀이 | override 없음, 코드 기본 1 | 여러 독립 후보 선택 기능과 동일하지 않음 |
| 회귀 검사·진단 근거 | override 없음, 코드 기본 false / false | 평가에서 켠 것과 구분 |

이는 **디스크 설정+코드 기본값 확인**이다. 환경변수·이미 적재된 앱 설정·현재 GPU에 올라간 모델을 별도로 조회한 완전한 실시간 상태는 아니다. 과거 문서의 “기본 120B 유지” 표현은 당시 문맥으로 읽고, 현재 파일의 27B 데스크톱 설정과 혼동하지 않는다.

## 10. RAM이 왜 중요하며, Mac Studio 256GB를 어떻게 봐야 하나

필요 메모리는 대략 **모델 가중치 + 긴 문맥의 KV 캐시 + 작업 버퍼 + 운영체제·앱**으로 나뉜다. 긴 문맥은 추가 메모리를 요구한다. 실제 증가량은 모델 구조·캐시 형식·동시 요청 등에 따라 달라진다. [Ollama 문맥 안내](https://docs.ollama.com/context-length).

현재 PC의 96GB RAM과 16GB VRAM은 분리돼 있다. RAM에 모델이 들어가도 전체를 GPU 속도로 계산할 수 있다는 뜻은 아니다. Apple Silicon은 CPU와 GPU가 같은 물리 메모리를 공유하는 구조다. 따라서 큰 모델과 긴 문맥을 함께 쓰는 데 용량 이점이 있을 수 있지만 **256GB 전부를 모델 하나에 할당할 수 있다고 계산하면 안 된다**. [Apple의 통합 메모리·MLX 설명](https://developer.apple.com/videos/play/wwdc2025/315/).

현재 대화에서의 구매 후보는 **M5 Ultra·256GB Mac Studio**이며 아직 구매하지 않았다. 이 문서는 최신 제품 가격·납기·구체 토큰 속도를 조사한 구매 견적이 아니다.

| 기대할 수 있는 변화 | 아직 확인해야 하는 것 |
|---|---|
| 더 큰 모델과 긴 문맥을 동시에 선택할 여지 | 그 큰 모델이 ALEX의 미해결 과제를 실제로 더 잘 푸는가 |
| 현재처럼 VRAM 부족으로 CPU에 넘기는 부담 감소 가능 | 해당 Mac·런타임·모델의 긴 입력 처리·첫 응답·전체 작업 시간 |
| 긴 파일을 덜 잘라 도구에 제공할 여지 | 문맥을 늘려도 정확히 찾고 추론하는가, 출력 예산이 충분한가 |
| 상시 로컬 AI 서버 운영 | 비용 대비 실제 사용 빈도·클라우드 감소·성공당 대기시간 |

**구매 판단을 위해 부족한 핵심 증거는 “RAM이 중요하냐”보다 “그 RAM으로 돌릴 모델·문맥 조합이 현재 실패를 얼마나 줄이느냐”다.** 지금은 장문+API의 이득이 관찰됐고, 대형 모델의 코딩 우위는 아직 측정해야 한다. 메모리 대역폭·연산 성능·런타임도 속도를 결정하므로 256GB만 보고 현재보다 몇 배 빠를 것이라고 계산하지 않는다.

## 12. 시험 문제와 문서 출력은 어디까지 가능한가

문제·해설·보고서 내용을 ALEX가 만들거나 사용자가 입력한 뒤 다음 명령으로 저장할 수 있다.

```text
/export xlsx last 문제은행
/export pdf last 시험지
/export pptx last 강의자료
/export docx last 해설집
/document docx 시험지 | 직접 작성한 문제 내용
```

- XLSX: Markdown 표를 별도 시트로, 나머지 본문도 보존. 현재 값은 문자열이며 계산 수식 자동 생성 기능이 아니다.
- DOCX: 제목·본문·코드·실제 Word 표. PPTX: 편집 가능한 텍스트와 긴 본문 슬라이드 분할, 표는 텍스트 행.
- PDF: 설치된 Edge/Chrome 계열 브라우저로 A4 출력. 지원 브라우저가 필요하다.
- 문제지·정답지 분리, 정답 검증, 차트·이미지 삽입·고급 수식 조판·맞춤 템플릿은 별도 기능이다.
- 관련 검증 **107 PASS·1 SKIP**, 네 형식 실파일 생성·독립 판독·PDF 한글 추출/렌더 확인. 실제 Microsoft Office 앱에서 모든 출력 사례를 열어 확인한 것은 아니다.

## 13. 앞으로 확인할 순서

1. **현재 대기열 완료 결과부터 수집**: v2와 v2+진단의 동일 ID·manifest·엄격 성공·의미상 수정·소요 시간을 짝 비교한다. 중간 5/6을 최종 성공률로 고정하지 않는다.
2. **진단 근거의 실제 이득 판단**: 남은 실패가 위치 탐색·외부 API·명세 추론·변경 형식 중 무엇인지 분리한다. 켰을 때 새 회귀·지연·불필요한 문맥 증가도 기록한다.
3. **검사 계약 보강**: 증상 우회가 통과한 사례에 경계값·본래 동작 검사를 추가할 후보를 정리한다. 기존 진행 중 평가/테스트는 바꾸지 말고 다음 버전에서 비교한다.
4. **대형 모델의 같은 과제 비교**: 안정적으로 실행할 수 있는 조건에서 27B와 120/125B를 같은 소스·하네스·예산으로 비교한다. 실패 과제 진단용 평가와 조정에 쓰지 않은 최종 평가를 구분한다.
5. **그 결과로 하드웨어·실사용 설정 판단**: 성공률뿐 아니라 성공당 시간·클라우드 대체량을 보고 장문/API/진단 채택 및 256GB 구매의 가치를 판단한다. 필요한 개선 폭과 비용 기준은 아직 사용자와 수치로 확정하지 않았다.
6. 이후 병목이 남으면 도구를 통한 반복 탐색·독립 후보 선택·추천 라우터를 순서대로 검토한다. 실제 가중치 훈련은 데이터·검사 품질과 독립 평가를 갖춘 뒤 별도 단계로 다룬다.

위 순서는 **후속 판단 가이드이며 이번 작업에서 실행한 변경이 아니다**. Claude의 진행 중 평가·얼린 소스·설정을 유지한다.
