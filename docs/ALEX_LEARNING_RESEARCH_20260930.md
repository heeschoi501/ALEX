# ALEX 로컬 AI 성장 기능 조사 (2026-09-30)

이 문서는 GitHub 공개 구현과 원 논문을 ALEX의 현재 구조에 대입한 **기능 제안**이다. 코드 변경이나 성능 검증 결과가 아니다.

## 현재 출발점

- ALEX는 SQLite에 대화·장기 메모·경험을 보관하고, 사용자 교정과 일부 웹 사실을 다음 답변의 교훈으로 사용한다. 이는 모델 가중치 학습과 다르다 (`LEARNING_AUDIT.md`, `jarvis/lessons.py`).
- `edit` 경험과 코딩 작업은 남지만, 테스트 결과·사용자 승인·실제 작업 성공이 재사용 가능한 교훈으로 이어지는 경로는 아직 약하다. `LEARNING_AUDIT.md`도 작업 outcome 연결을 첫 후속 과제로 꼽는다.
- `/dev-auto`는 격리된 복사본에서 최대 세 번 수정·시험하고 실제 반영은 사용자 승인으로 제한한다 (ADR-066). 이 구조를 학습 신호의 출처로 활용할 수 있다.
- `training_runs`와 학습용 내보내기는 있지만 실제 LoRA 훈련·검증·채택 절차는 없다. 2026-09-25 점검 당시 훈련 실행은 0건이었다. 현재 DB 건수는 다시 확인해야 한다.

## 우선순위 1 — 작업 결과를 증거와 함께 기록

**제안:** 코딩 작업마다 목표, 파일, 모델/설정, 시험 명령과 종료 코드, 실패 요약, 수정안 ID, 사용자 승인/거절, 적용 후 전체 검사 결과를 하나의 `outcome`으로 연결한다. 상태는 `미검증 / 실패 / 선택 검사 통과 / 전체 검사 통과 / 사용자 채택`처럼 구분한다. 테스트가 검출하지 못한 의미상 오류도 별도 표시한다.

**이유:** 지금은 경험이 저장돼도 무엇이 실제로 성공했는지 확인할 수 있어야 다음 학습의 재료가 된다. [Reflexion 원 논문](https://arxiv.org/abs/2303.11366)은 환경의 피드백을 말로 된 반성 기록에 연결하고 다음 시도에 활용한다. [공식 코드](https://github.com/noahshinn/reflexion)는 코딩 과제 실행 기록을 포함한다. ALEX에서는 모델의 자기평가보다 테스트 결과와 사용자 판단을 우선해야 한다.

**첫 검증:** 기존 코딩 평가 과제에서 각 회차의 결과와 최종 적용 결과가 정확히 연결되는지 확인한다. 테스트가 놓친 `webread` 사례처럼 ‘테스트 통과=정답’으로 기록되는 사례가 없어야 한다.

## 우선순위 2 — 성공·실패에서 짧은 교훈을 추출하고 다시 검증

**제안:** 완료된 작업의 증거에서 ‘상황 → 실패 원인/성공한 절차 → 적용 조건 → 출처 작업 ID’를 짧게 생성한다. 모델이 쓴 교훈은 후보로 두고, 같은 종류의 새 과제에서 유효할 때만 활성화한다. 잘못된 교훈은 취소하고 원본 실행 기록은 보존한다.

**근거:** [ExpeL 논문](https://arxiv.org/abs/2308.10144)과 [공식 구현](https://github.com/LeapLabTHU/ExpeL)은 작업 경험을 모으고 자연어 통찰을 추출한 뒤 유사 작업에서 재사용한다. Reflexion은 한 작업의 실패 피드백을 다음 시도에 쓰는 더 좁은 패턴이다. 두 연구 모두 가중치를 바꾸지 않고 개선하는 경로다.

**ALEX에 맞는 예:** `developer_any_test_fails`에서 ‘여러 테스트 중 하나라도 실패하면 실패 처리’라는 조건을 교훈 후보로 만들되, 모델이 만든 비슷한 함수가 원래 동작을 보존했는지 시험 결과와 연결한다. 실패 로그만 보고 일반 규칙으로 승격하지 않는다.

**첫 검증:** 과제별 교훈 사용 on/off를 비교한다. 같은 버그의 반복 실행만으로 성장을 주장하지 않고, 교훈 작성에 쓰지 않은 변형 과제에서 성공률·불필요한 변경·소요 시간·토큰 수를 함께 측정한다.

## 우선순위 3 — 필요한 경험만 정확히 찾기

**제안:** 기존 단어 겹침 검색을 기준선으로 두고, 출처·프로젝트·작업 종류·승인 상태·시효를 필터로 추가한다. 그다음 SQLite FTS5와 로컬 임베딩을 후보로 비교한다. 검색된 교훈은 근거 ID를 답변과 작업 기록에 남긴다. 한국어와 코드 식별자 검색은 별도 평가한다.

**근거:** [LongMemEval](https://github.com/xiaowu0162/LongMemEval)은 장기 기억에서 정보 추출, 세션 간 추론, 시간 변화, 지식 갱신, 모름 판단을 평가한다. [LongMemEval-V2](https://github.com/xiaowu0162/LongMemEval-V2)는 작업 궤적에서 절차와 환경별 함정을 기억하는 능력까지 평가한다. [SQLite FTS5 문서](https://www.sqlite.org/fts5.html)는 로컬 전문 검색과 BM25 정렬을 제공한다. FTS5는 저장소 선택지이며, 한국어 검색 품질 개선은 실측 전까지 가정하지 않는다.

**첫 검증:** ALEX의 실제 교정·코딩 기록으로 질문과 정답 경험 ID를 묶은 작은 검색 세트를 만든다. Recall@3, 잘못 가져온 교훈 수, 평균 지연, 답변 품질을 현재 검색과 비교한다.

## 우선순위 4 — 검증된 작업 절차를 Skill로 저장

**제안:** 여러 번 성공한 작업에서만 ‘언제 사용 / 필요한 입력 / 허용된 단계 / 성공 기준 / 되돌리는 방법’이 있는 절차를 만든다. 처음에는 실행 코드가 아닌 읽기 전용 안내로 제공하고, 실행은 기존 `/dev-check` 허용 목록과 사용자 승인 흐름 안에서만 한다. 오래된 Skill은 재검증하거나 폐기한다.

**근거:** [Voyager 논문](https://arxiv.org/abs/2305.16291)과 [공식 Skill 라이브러리](https://github.com/MineDojo/Voyager/blob/main/skill_library/README.md)는 성공한 동작을 검색 가능한 기술로 축적한다. [Agent Workflow Memory 논문](https://arxiv.org/abs/2409.07429)은 과거 실행에서 반복 사용 가능한 작업 흐름을 추출한다. 이 연구의 실험 환경은 ALEX와 다르므로 설계 아이디어만 가져온다.

**첫 검증:** 동일 종류의 새 코딩 작업에서 Skill 사용 전후의 성공률, 회차 수, 군더더기 수정 수를 비교한다. 한 번 성공한 절차는 자동으로 영구 Skill이 되지 않는다.

## 우선순위 5 — 독립 평가와 제한된 자동 개선 제안

**제안:** 학습에 쓴 작업과 평가 작업을 분리하고, 같은 모델·설정에서 교훈/Skill on/off를 비교한다. ALEX가 실패 유형을 분류하고 프롬프트·검색·Skill 수정안을 제안하더라도 승격은 별도 평가와 사용자 승인 뒤에 한다. 실패 유형에는 `형식 오류`, `시간 초과`, `테스트 실패`, `불필요한 변경`, `검색 누락`, `오래된 기억`을 포함한다.

**근거:** [DSPy의 GEPA 문서](https://github.com/stanfordnlp/dspy/blob/main/docs/docs/getting-started/gepa-optimization.md)는 평가 피드백을 이용한 프롬프트 개선 방식을 설명한다. [DSPy 로컬 모델 연결 문서](https://github.com/stanfordnlp/dspy/blob/main/docs/docs/learn/programming/language_models.md)는 Ollama 사용 예를 제공한다. ALEX에 DSPy 전체를 설치할 필요는 없고, 평가 기준과 후보 프롬프트 비교 방식부터 참고할 수 있다.

## 가중치 학습(LoRA)은 마지막 단계

[LoRA 원 논문](https://arxiv.org/abs/2106.09685)과 [Hugging Face PEFT 문서](https://huggingface.co/docs/peft/main/package_reference/lora)는 적은 수의 추가 매개변수를 학습하는 방법을 제공한다. 그러나 ALEX에는 아직 충분한 **검증·승인된** 작업 데이터와 독립 회귀 평가가 없다. 현 시점에는 가중치 학습 자동화를 넣는 것보다 위의 결과 기록 → 교훈 추출 → 검색 → 독립 평가가 우선이다. 이 단계는 현재 PC와 기존 로컬 모델로 시작할 수 있으므로 Mac Studio 구매의 선행 조건이 아니다.

## 권장 구현 순서와 통과 기준

| 순서 | 최소 단위 | 통과 기준 |
| --- | --- | --- |
| 1 | 코딩 작업 `outcome` 연결 | 실행 기록과 적용 후 검사·사용자 판단을 누락 없이 구분 |
| 2 | 교훈 후보 생성과 취소 | 출처와 검증 상태가 보이고, 취소 후 재사용되지 않음 |
| 3 | 검색 비교 | 현재 검색보다 정답 경험 Recall@3 또는 최종 작업 성공률 개선, 오검색 악화 없음 |
| 4 | 읽기 전용 Skill | 별도 과제에서 회차 수 또는 성공률 개선, 불필요한 수정 증가 없음 |
| 5 | 자동 개선 제안 | 독립 평가를 통과한 후보만 사람이 채택 가능 |
| 6 | LoRA 실험 | 승인 데이터·고정 평가·되돌리기·기존 정체성 검사 준비 후 착수 |

**결론:** ALEX에 가장 먼저 필요한 ‘학습 능력’은 더 큰 모델이나 자동 재훈련이 아니라, 실제 결과를 증거로 남기고 검증된 교훈을 다음 작업에 골라 쓰며 그 효과를 독립적으로 재는 고리다.
