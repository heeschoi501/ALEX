## 작업 규칙(이번에 배운 것)

- **push 하기 전:** `python scripts/verify_release.py` 와 `node scripts/verify_web_ui.cjs python` 을 돌린다. push 하면 GitHub Actions 가 같은 검사를 리눅스·Windows 에서 다시 돌린다. 빨간 CI 는 다음 일보다 먼저 고친다.
- **경로 비교:** 한쪽만 `resolve()` 하지 않는다. Windows 의 `C:\Users\RUNNER~1` 과 `runneradmin` 이 다른 경로로 잡혀 두 번 깨졌다. 포함 여부는 양쪽 다 푼 경로로 비교하고, 링크 검사는 넘겨받은 루트 아래에서만 한다. Linux 에서는 링크로 된 임시 폴더로 재현한다(`TMPDIR=<링크 폴더> python scripts/run_suite.py`).
- **시험에 넣는 가짜 비밀값:** `tests/` 와 `scripts/security_smoke.py` 에만 둔다. 그 밖에 두면 gitleaks 가 막는다. 걸리면 진짜 키로 보고 새로 발급받는다.
- **원본 점검:** `python -X utf8 scripts/check_upstreams.py`. 종료 코드 1 이면 점검 실패부터 해결한다. 원본이 바뀌면 판정을 `history` 에 남기고 `ref`·`commit` 을 옮긴다. `checked` 는 사람이 판정한 날짜다.
- **고침마다 시험:** 새 시험이 고치기 전에는 실패하고 고친 뒤에는 통과하는지 확인한다. 틀린 이유로 통과하는 시험이 없도록 거절 이유까지 확인한다(`assertRaisesRegex`).
