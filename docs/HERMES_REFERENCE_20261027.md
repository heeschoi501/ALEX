Claude 검토에 이어 Codex가 같은 커밋 `085f562af53a6fedadac3681e2c498fc71316132`의 원본과 ALEX를 다시 대조했다. 그대로 옮긴 코드는 `jarvis/threats.py`의 패턴 목록이며 라이선스 전문은 `jarvis/HERMES_LICENSE.txt`에 있다. 새 스킬·프로필 기능은 방식을 참고해 ALEX 표준 라이브러리 코드로 작성했다.

## 승인형 라이브러리와 프로필 사용

공개 [Agent Skills 형식](https://github.com/agentskills/agentskills)의 `SKILL.md`(name·description 머리말 + Markdown 지침)를 사용한다. 가져올 때 references/·scripts/·assets/ 등 보조 파일도 묶음으로 보존한다. 이름은 영문 소문자·숫자·하이픈, 최대 64자이며 단순/따옴표/블록 description을 지원한다. 묶음은 최대 40파일·512KB, SKILL.md는 8,000자다. 임의 YAML 확장·전처리 셸 실행·허브 자동 설치는 지원하지 않는다.

관리자 채팅·CLI에서:

1. 작업을 마친 대화에서 `/growth review` — 로컬 일반 모델이 최대 3개 변경안을 제안한다. 사용자 발언 번호·발췌를 근거로 남긴다. 모델이 참인 사실·성공한 절차를 정확히 골랐는지는 사람이 확인한다.
2. `/growth pending`, `/growth show 제안번호` — 변경 diff·근거·묶음 파일 목록을 본다. 보조 파일은 `/growth show 제안번호 scripts/check.py`처럼 따로 읽는다.
3. `/growth approve 제안번호` 또는 `/growth reject 제안번호` — 제안 뒤 승인본이나 제안 파일이 바뀌면 승인을 거절한다. 승인되지 않은 자료는 프롬프트·스킬 목록에 넣지 않는다.
4. `/growth skills`, `/growth profile` — 승인된 스킬과 USER.md·MEMORY.md를 확인한다. 프로필·메모는 새 대화부터 반영되며 진행 중인 대화의 snapshot은 바뀌지 않는다.
5. `/growth import 상대경로/스킬/SKILL.md` — 관리자가 승인한 프로젝트 안의 묶음을 제안으로 가져온다. 심볼릭 링크·junction·비밀 파일·범위 밖 경로는 거절한다. 가져오기·승인 과정에서 scripts를 실행하지 않는다. 출처 LICENSE 파일도 묶음에 포함해 보존한다.
6. `/growth archive 이름`, `/growth restore 이름` — 수동 보관, 승인 후 되살리기. 새 스킬 버전이 승인될 때도 이전 묶음은 보관한다.
7. `/growth auto on` / `/growth auto off` — 웹 앱의 기존 유휴 루프에서 PC 주인만 자동 검토. 대화 차례가 먼저이며 시작한 검토 한 번은 끝날 때까지 실행한다. 모델 한 번 호출로 제한하고 출력 상한을 둔다. GUI 없이 CLI만 실행할 때는 수동 review를 쓴다.

저장소는 `data_dir/growth/<사용자 ID의 SHA256>/` 아래다. profile·memory·skills와 대기 제안은 사용자별로 분리된다. 코딩 하네스는 승인된 스킬의 목록·필요한 본문을 읽으며 기존 도구 권한을 유지한다. 일반 로컬 대화에서는 요청과 겹치는 단어가 있는 승인 스킬 하나만 제한된 길이로 참고한다. 이 선택은 어림이며 품질은 PC에서 평가해야 한다.

승인된 개인 문맥은 잘라낸 뒤에도 `Message.local_only`가 유지돼 클라우드 요청에서 제외된다. 그 문맥을 쓴 대화는 별도 비공개 표시를 남겨 기존 이력 제외 처리에 연결하므로 이후 클라우드 요청에도 이전 답·요약이 섞이지 않는다. 이 표시는 웹 검색 자동 선택 조건과 구분한다. 외부 모델 복사·`/cloud` 복사에서는 `growth` 폴더 전체를 제외한다. 파일 필터는 OS 실행 격리와 구분한다.

## PC 에서 할 것

1. `python -X utf8 scripts/measure_prompt_cache.py --live --pairs 4` — 준비 요청을 제외하고 같은 기록을 끔/켬·켬/끔 순서로 비교한다. 사전 기준과 해석은 [성장 보고서 8절](GROWTH_ABSORPTION_REPORT_20261027.md#8-검토-반영과-측정-판정-기준). 실제 캐시 적중률은 이 스크립트가 직접 측정하지 않는다.
2. 실제 로컬 모델의 배움 제안: 확정 사실·일시 정보·실패·사용자 교정을 섞은 대화에서 제안 근거와 기존 내용 보존을 확인한다. 실모델 품질 검증 전 자동 검토 기본값은 꺼짐이다.
3. Windows OpenCode·일반/코딩 세션의 스킬 사용·프록시/CA 환경·junction 제외를 실제 PC에서 확인한다.

## 한계

- 순서를 바꾸면 교훈·자료가 질문에 더 가까워진다. 답의 질이 달라질 수 있어 기본은 꺼 두었다.
- 주입 패턴은 어림이다. 검사에 안 걸린 지시도 있을 수 있어 '지시로 따르지 말라' 안내는 그대로 둔다. 이 저장소의 문서 85개에서는 하나도 걸리지 않았다.
- 대화 본문 검색은 색인 없이 훑는다. 대화가 수십만 개로 늘면 느려질 수 있다(지금은 최근 일치 2,000개까지만 본다).
- 새 제안은 대기 20개·결정 기록 200개 한도다. 한도에 닿으면 새 제안을 거절하며 조용히 기존 제안을 지우지 않는다. 이전 버전·거절한 묶음은 로컬에 남으므로 장기 보관 정리는 후속이다.
- 파일·제안 내용은 OS 사용자가 직접 바꿀 수 있다. 동시 다중 프로세스 쓰기와 OS 수준 격리는 보장하지 않는다. 스킬 선택·제안 품질·프롬프트 성능 개선은 실모델로 아직 확인하지 않았다.
